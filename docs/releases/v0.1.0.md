### Deployment chronology

- [Run 30728180877](https://github.com/Neuralstock/neuralstock/actions/runs/30728180877)
  exposed Cloudflare's real `ObjectLockedByBucketPolicy` response shape after
  staging the twelve fresh contract objects; aliases, lock rules, and the site
  were unchanged.
- [Run 30728900823](https://github.com/Neuralstock/neuralstock/actions/runs/30728900823)
  failed before mutation because a shallow checkout lacked the verified
  ancestry graph.
- [Run 30729693309](https://github.com/Neuralstock/neuralstock/actions/runs/30729693309)
  completed Phase A and retained byte-exact alias guards.
- [Run 30730280063](https://github.com/Neuralstock/neuralstock/actions/runs/30730280063)
  published the correct aliases and Pages build, then its final verifier stopped
  on a stale sitemap during Pages edge propagation. Follow-up local probes
  observed discovery convergence and R2's valid `206` omission of advisory
  `Accept-Ranges`, motivating the bounded-retry and strict normative-range patch
  in PR #13.
- [Run 30730929891](https://github.com/Neuralstock/neuralstock/actions/runs/30730929891)
  completed Phase B on protected controller `181e0d661e0e9f6d662e1bc18ecdc37dc38d9cff`:
  it rebound the eight lock rules and 227 immutable objects to the exact
  candidate plan, updated both aliases, deployed Pages as `de6d320c`, and
  passed the complete live verifier for the fifteen-entry registry and sitemap
  plus representative first-entry artifact delivery.

Failed runs are retained because each exposed and then closed a fail-safe
automation assumption; none rewrote an immutable release object.

### Known limitations and follow-ups

- `cabinet_01@1.0.1` has authored z-fighting: blue door surfaces and green/pull
  overlays share the `y=-0.270` plane in `blender/generators_furniture.py`.
  Its published GLB (`e9e11e81f4e9791a2253f2daa7b5e136f7e57f7cb4a258b3e91c4d0c817353f8`,
  130,584 bytes) and source
  (`733c9fd519a0a720d841e9b75c6f603e57ed77f773ade6f6e3fe252ba240bc79`,
  540,741 bytes) are complete and byte-verified, so this is a medium visual and
  credibility issue with low functional or integrity impact—not CDN corruption.
  Immutable 1.0.1 remains unchanged. The repair is a new `cabinet_01@1.0.2`
  with at least 1 mm surface separation and a coplanar-overlap regression test.
- Local GitHub CLI 2.82.1 may report no immutable-release attestation while the
  GitHub API exposes it. The hosted finalizer observed initial propagation,
  then successfully verified the release and every asset. Until local CLI
  behavior converges, the hosted run and API readback are the recorded gate.
- npm's first namespace-creating upload could not carry GitHub OIDC provenance;
  it was the exact GitHub-attested candidate and used interactive 2FA. The
  trusted publisher is now configured for subsequent versions.
- The narrowly scoped GitHub admin-read credential used only to inspect the
  immutable-releases setting is time-limited. Remove or renew it before its
  early-September 2026 expiry; never replace it with a broad persistent token.
